## 快速开始

### 第一步：注册账号

1. 访问 http://localhost:5173
2. 点击"注册"按钮
3. 填写用户名、邮箱和密码
4. 完成注册并登录

### 第二步：上传数据集

1. 进入"数据集管理"页面
2. 点击"上传数据集"按钮
3. 填写数据集信息：
   - 名称：数据集名称
   - 格式：选择 COCO、VOC 或 YOLO 格式
   - 描述：数据集说明
4. 上传 ZIP 压缩包
5. 等待数据集处理完成

### 第三步：创建训练任务

1. 进入"训练管理"页面
2. 点击"创建训练"按钮
3. 配置训练参数：
   - 任务名称
   - 模型版本（YOLOv5/v8/v9/v10）
   - 选择数据集
   - 训练参数（epochs、batch_size 等）
4. 点击"开始训练"

### 第四步：查看训练进度

1. 在训练列表中找到正在训练的任务
2. 点击查看详情
3. 实时查看：
   - 训练进度
   - Loss 曲线
   - mAP 指标
   - 训练日志

### 第五步：测试模型

1. 训练完成后，进入"测试中心"
2. 选择训练好的模型
3. 上传测试图片
4. 查看检测结果

## 数据集管理

### 支持的数据格式

#### YOLO 格式

```
dataset/
├── images/
│   ├── train/
│   │   ├── image1.jpg
│   │   └── image2.jpg
│   └── val/
│       ├── image3.jpg
│       └── image4.jpg
├── labels/
│   ├── train/
│   │   ├── image1.txt
│   │   └── image2.txt
│   └── val/
│       ├── image3.txt
│       └── image4.txt
└── dataset.yaml
```

**dataset.yaml 示例：**
```yaml
train: ./images/train
val: ./images/val

nc: 3
names: ['person', 'car', 'dog']
```

**标注格式（每行一个目标）：**
```
class_id x_center y_center width height
0 0.5 0.5 0.3 0.4
1 0.2 0.3 0.1 0.2
```

#### COCO 格式

```json
{
  "images": [
    {
      "id": 1,
      "file_name": "image1.jpg",
      "width": 640,
      "height": 480
    }
  ],
  "annotations": [
    {
      "id": 1,
      "image_id": 1,
      "category_id": 0,
      "bbox": [100, 150, 200, 250],
      "area": 50000,
      "iscrowd": 0
    }
  ],
  "categories": [
    {
      "id": 0,
      "name": "person"
    }
  ]
}
```

### 上传数据集

1. 将数据集打包成 ZIP 文件
2. 确保目录结构符合规范
3. 在"数据集管理"页面上传
4. 等待处理完成（通常 1-5 分钟）

### 数据集统计

上传成功后，系统会自动统计：
- 图片总数
- 标注总数
- 各类别分布
- 训练/验证/测试集划分

### 数据增强配置

在训练时可以配置数据增强：

```json
{
  "augmentation": {
    "hsv_h": 0.015,
    "hsv_s": 0.7,
    "hsv_v": 0.4,
    "degrees": 0.0,
    "translate": 0.1,
    "scale": 0.5,
    "shear": 0.0,
    "perspective": 0.0,
    "flipud": 0.0,
    "fliplr": 0.5,
    "mosaic": 1.0,
    "mixup": 0.0
  }
}
```

## 模型训练

### 支持的模型版本

| 模型 | 特点 | 推荐场景 |
|------|------|---------|
| YOLOv5n | 轻量级，速度快 | 移动端部署 |
| YOLOv5s | 平衡速度和精度 | 通用场景 |
| YOLOv5m | 中等模型 | 需要更高精度 |
| YOLOv5l | 大模型 | 高精度需求 |
| YOLOv5x | 超大模型 | 最高精度 |
| YOLOv8n | 最新轻量级 | 移动端部署 |
| YOLOv8s | 最新平衡型 | 通用场景 |
| YOLOv8m | 最新中等模型 | 需要更高精度 |
| YOLOv8l | 最新大模型 | 高精度需求 |
| YOLOv8x | 最新超大模型 | 最高精度 |
| YOLOv9c | 高效架构 | 资源受限场景 |
| YOLOv9e | 增强版 | 更高精度 |
| YOLOv10n | 最新轻量级 | 实时检测 |
| YOLOv10s | 最新平衡型 | 通用场景 |

### 训练参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| epochs | 100 | 训练轮数 |
| batch_size | 16 | 批量大小 |
| img_size | 640 | 输入图片尺寸 |
| learning_rate | 0.01 | 学习率 |
| optimizer | Adam | 优化器（SGD/Adam/AdamW） |
| patience | 50 | 早停轮数 |
| workers | 8 | 数据加载线程数 |
| device | 0 | GPU 编号 |
| amp | true | 自动混合精度 |
| cache | false | 数据缓存（ram/disk） |

### 创建训练任务

**方式一：Web UI**

1. 点击"训练管理" -> "创建训练"
2. 填写表单：
   ```
   任务名称：yolov8n-custom
   模型版本：YOLOv8n
   数据集：my-dataset
   训练轮数：100
   批量大小：16
   图片尺寸：640
   ```
3. 点击"开始训练"

**方式二：API**

```python
import requests

data = {
    "name": "yolov8n-custom",
    "model_version": "yolov8n",
    "dataset_id": "dataset-uuid",
    "config": {
        "epochs": 100,
        "batch_size": 16,
        "img_size": 640,
        "learning_rate": 0.01
    }
}

response = requests.post(
    "http://localhost:8000/api/v1/trainings",
    json=data,
    headers={"Authorization": "Bearer your_token"}
)

print(response.json())
```

### 监控训练进度

**实时指标：**
- Train Loss：训练损失
- Val Loss：验证损失
- mAP50：IoU=0.5 时的平均精度
- mAP50-95：IoU=0.5:0.95 时的平均精度
- Precision：精确率
- Recall：召回率

**查看日志：**
```bash
# 通过 API 获取日志
curl http://localhost:8000/api/v1/trainings/{id}/logs

# 通过 WebSocket 实时推送
ws://localhost:8000/ws/trainings/{id}
```

### 断点续训

如果训练中断，可以从 checkpoint 继续训练：

```json
{
  "config": {
    "resume": true,
    "checkpoint": "path/to/last.pt"
  }
}
```

## 模型测试

### 单图测试

1. 进入"测试中心"
2. 选择模型
3. 上传图片
4. 调整参数：
   - 置信度阈值（0-1）：过滤低置信度检测
   - IoU 阈值（0-1）：NMS 阈值
5. 点击"开始测试"
6. 查看结果：
   - 检测框
   - 类别标签
   - 置信度分数
   - 推理时间

### 批量测试

1. 选择"批量测试"
2. 上传多张图片或 ZIP 文件
3. 选择模型和参数
4. 开始测试
5. 下载结果：
   - 带检测框的图片
   - JSON 格式检测结果
   - 统计报告

### 测试结果解读

**检测结果示例：**
```json
{
  "detections": [
    {
      "class": "person",
      "class_id": 0,
      "confidence": 0.923,
      "bbox": {
        "x1": 100,
        "y1": 150,
        "x2": 300,
        "y2": 400
      }
    }
  ]
}
```

**指标说明：**

| 指标 | 说明 |
|------|------|
| Precision | 精确率：预测为正样本中实际为正的比例 |
| Recall | 召回率：实际为正样本中被预测为正的比例 |
| mAP50 | IoU=0.5 时的平均精度 |
| mAP50-95 | IoU=0.5:0.95 时的平均精度 |
| F1 Score | Precision 和 Recall 的调和平均 |

## 模型对比

### 选择模型进行对比

1. 进入 **模型管理** → **模型对比** 页面
2. 在模型列表中勾选要对比的模型（支持 2-6 个）
3. 可通过搜索框按名称、标签或训练时间筛选模型
4. 也可以直接从训练历史中点击"加入对比"按钮

**操作步骤：**

1. 点击"新建对比"按钮
2. 选择对比方式：
   - **选择已有模型**：从模型列表中勾选
   - **上传模型文件**：上传 `.pt` / `.onnx` 格式的模型文件
3. 点击"开始对比"

### 对比指标说明

| 指标 | 说明 | 参考范围 |
|------|------|----------|
| mAP50 | IoU=0.5 时的平均精度 | 越高越好，≥0.5 为良好 |
| mAP50-95 | IoU=0.5:0.95 的平均精度 | 越高越好，≥0.3 为良好 |
| Precision | 精确率 | 越高越好 |
| Recall | 召回率 | 越高越好 |
| F1 Score | 精确率和召回率的调和平均 | 越高越好 |
| FPS | 每秒推理帧数 | 越高越好，≥30 为实时 |
| 模型大小 | 模型文件体积 | 根据部署场景选择 |
| 参数量 | 模型总参数数量 | 影响模型复杂度 |
| FLOPs | 浮点运算次数 | 影响推理速度 |

### 结果解读

对比结果包含以下几个部分：

**1. 指标对比表**

以表格形式展示各模型在各项指标上的表现，最优值会高亮显示。

**2. 可视化对比图**

- **PR 曲线对比**：查看不同模型在各置信度阈值下的 Precision-Recall 表现
- **柱状图对比**：直观对比各指标数值
- **雷达图**：多维度综合对比模型性能

**3. 检测结果对比**

上传测试图片后，可并排查看各模型的检测结果，包括：
- 检测框位置和大小
- 类别标签和置信度
- 推理时间

**4. 导出对比报告**

点击"导出报告"按钮，可下载包含所有对比数据的 PDF 或 CSV 文件。

> 💡 **提示**：建议在同一测试集上对比模型，以确保结果的公平性和可比性。

## 超参搜索

超参搜索功能帮助您自动找到最优的训练超参数组合，无需手动反复尝试。

### 配置搜索空间

1. 进入 **训练管理** → **超参搜索** 页面
2. 点击"新建搜索任务"
3. 配置基础信息：
   - 任务名称
   - 选择数据集
   - 选择基础模型

4. 配置搜索空间：

```yaml
# 搜索空间配置示例
search_space:
  learning_rate:
    type: log_uniform    # 对数均匀采样
    min: 0.0001
    max: 0.1
  
  batch_size:
    type: choice         # 从候选值中选择
    values: [8, 16, 32, 64]
  
  epochs:
    type: int_uniform    # 整数均匀采样
    min: 50
    max: 300
  
  optimizer:
    type: choice
    values: ["SGD", "Adam", "AdamW"]
  
  img_size:
    type: choice
    values: [416, 512, 640]
  
  weight_decay:
    type: log_uniform
    min: 0.00001
    max: 0.001
  
  momentum:
    type: uniform        # 均匀采样
    min: 0.85
    max: 0.99
```

**参数类型说明：**

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| `uniform` | 均匀采样 | 连续值参数 |
| `log_uniform` | 对数均匀采样 | 学习率等跨越多个数量级的参数 |
| `int_uniform` | 整数均匀采样 | epochs、workers 等整数参数 |
| `choice` | 离散选择 | 优化器、模型版本等枚举值 |

### 选择搜索算法

系统支持以下搜索算法：

| 算法 | 说明 | 推荐场景 |
|------|------|----------|
| **随机搜索** | 随机采样参数组合 | 快速探索，基准对比 |
| **贝叶斯优化** | 基于历史结果智能推荐下一组参数 | 搜索空间较大，预算有限 |
| **网格搜索** | 遍历所有参数组合 | 参数较少，需要穷举 |
| **Hyperband** | 基于早停的高效搜索 | 训练耗时较长的场景 |
| **PBT** | Population Based Training | 有充足计算资源时 |

**选择建议：**
- 初次探索：推荐使用 **随机搜索**（10-20 组试验）
- 精细调优：推荐使用 **贝叶斯优化**（30-50 组试验）
- 参数空间小：使用 **网格搜索**

### 查看搜索结果

搜索任务启动后，可以实时查看进度：

**1. 搜索进度面板**

- 当前试验编号 / 总试验数
- 当前最优指标值
- 预计剩余时间

**2. 试验结果列表**

| 字段 | 说明 |
|------|------|
| Trial ID | 试验编号 |
| 状态 | 运行中 / 完成 / 失败 |
| mAP50 | 最终 mAP50 指标 |
| 参数 | 本次使用的超参数组合 |
| 耗时 | 训练时长 |

**3. 参数重要性分析**

系统会自动分析各超参数对最终指标的影响程度，帮助您：
- 识别关键参数
- 缩小后续搜索范围
- 理解参数间的交互关系

**4. 并行坐标图**

以并行坐标图展示所有试验的参数和结果关系，支持：
- 按指标排序
- 高亮最优试验
- 筛选特定参数范围

**5. 查看最优参数**

搜索完成后，系统会自动标注最优参数组合：

```json
{
  "best_params": {
    "learning_rate": 0.0052,
    "batch_size": 32,
    "epochs": 200,
    "optimizer": "AdamW",
    "img_size": 640,
    "weight_decay": 0.00012,
    "momentum": 0.93
  },
  "best_metric": {
    "mAP50": 0.876,
    "mAP50-95": 0.654
  }
}
```

> 💡 **提示**：可直接点击"使用最优参数创建训练"，一键基于最优参数开始正式训练。

## 模型部署

模型部署功能支持将训练好的模型一键部署到多种目标平台。

### 选择部署平台

1. 进入 **模型管理** → **部署中心**
2. 点击"新建部署"
3. 选择目标平台：

| 平台 | 说明 | 导出格式 | 适用场景 |
|------|------|----------|----------|
| **ONNX Runtime** | 通用推理引擎 | ONNX | CPU/GPU 通用部署 |
| **TensorRT** | NVIDIA GPU 优化 | TensorRT | NVIDIA GPU 服务器 |
| **OpenVINO** | Intel 硬件优化 | IR | Intel CPU/GPU |
| **CoreML** | Apple 设备优化 | CoreML | iPhone/iPad/Mac |
| **TFLite** | 移动端推理 | TFLite | Android/嵌入式 |
| **Edge TPU** | Google Edge TPU | TFLite (量化) | Coral 设备 |
| **Docker 容器** | 容器化部署 | 任意 | 服务器集群 |
| **Kubernetes** | K8s 集群部署 | Docker | 大规模生产环境 |

### 配置部署参数

根据选择的平台，配置对应的部署参数：

**通用参数：**

```yaml
deployment:
  name: "yolov8n-production"
  model_id: "model-uuid-here"
  platform: "onnxruntime"         # 部署平台
  
  # 模型优化选项
  optimize:
    quantize: true                 # 是否量化
    quantize_type: "int8"          # 量化精度 (int8/fp16)
    prune: false                   # 是否剪枝
    prune_ratio: 0.3              # 剪枝比例
  
  # 推理配置
  inference:
    input_size: [640, 640]        # 输入尺寸
    conf_threshold: 0.25          # 置信度阈值
    iou_threshold: 0.45           # NMS IoU 阈值
    max_detections: 100           # 最大检测数量
    batch_size: 1                 # 推理批量大小
  
  # 资源配置
  resources:
    replicas: 2                   # 副本数
    cpu_limit: "2"                # CPU 限制
    memory_limit: "4Gi"           # 内存限制
    gpu_enabled: true             # 是否使用 GPU
    gpu_type: "T4"                # GPU 型号
```

**TensorRT 特有参数：**

```yaml
tensorrt:
  precision: "fp16"               # 推理精度 (fp32/fp16/int8)
  workspace_size: 4               # 工作空间大小 (GB)
  dynamic_axes:                   # 动态维度
    images: [0]
    outputs: [0]
```

**Docker 容器参数：**

```yaml
docker:
  base_image: "nvcr.io/nvidia/tritonserver:23.10-py3"
  ports: [8000, 8001, 8002]
  volumes:
    - "/models:/models"
  environment:
    - "MODEL_REPOSITORY=/models"
```

### 监控部署状态

部署完成后，可以在部署详情页监控以下信息：

**1. 部署状态**

| 状态 | 说明 |
|------|------|
| 🟢 运行中 | 服务正常运行 |
| 🟡 部署中 | 正在部署/更新 |
| 🔴 异常 | 服务出现问题 |
| ⚫ 已停止 | 服务已停止 |

**2. 性能监控**

- **请求量**：每秒处理的请求数
- **延迟**：P50 / P95 / P99 推理延迟
- **吞吐量**：每秒处理的图片数
- **错误率**：请求失败比例
- **GPU 利用率**：GPU 资源使用情况
- **内存使用**：内存占用趋势

**3. 健康检查**

系统会自动执行健康检查，并在异常时发出告警：
- API 端点可用性检查
- 推理结果正确性校验
- 资源使用率阈值告警

**4. 版本管理**

- 支持蓝绿部署（零停机更新）
- 支持灰度发布（按比例分流）
- 支持一键回滚到上一版本

**API 调用示例：**

```python
import requests

# 调用已部署的模型
response = requests.post(
    "http://your-deployment-url:8000/v2/models/yolov8n/infer",
    json={
        "inputs": [
            {
                "name": "images",
                "shape": [1, 3, 640, 640],
                "datatype": "FP32",
                "data": image_data
            }
        ]
    }
)

print(response.json())
```

> 💡 **提示**：部署后可在"测试中心"直接选择已部署的模型进行在线测试，无需重新上传模型文件。

## 团队协作

团队协作功能支持多人协作管理数据集、训练任务和模型。

### 创建团队

1. 进入 **设置** → **团队管理**
2. 点击"创建团队"
3. 填写团队信息：
   - 团队名称（如 "AI-Vision-Team"）
   - 团队描述
   - 团队头像（可选）
4. 点击"确认创建"

创建完成后，您将成为团队的 **所有者**，拥有最高权限。

### 添加/移除成员

**添加成员：**

1. 在团队管理页面点击"添加成员"
2. 输入成员的用户名或邮箱
3. 选择成员角色（管理员 / 开发者 / 查看者）
4. 点击"发送邀请"
5. 成员接受邀请后即加入团队

**批量添加：**

支持通过 CSV 文件批量导入成员：

```csv
email,role
alice@example.com,admin
bob@example.com,developer
charlie@example.com,viewer
```

**移除成员：**

1. 在成员列表中找到目标成员
2. 点击成员右侧的"移除"按钮
3. 确认移除操作

> ⚠️ **注意**：移除成员后，该成员将无法访问团队的任何资源，但其创建的资源（数据集、训练任务等）仍保留在团队中。

## 活动日志

活动日志记录了团队和系统中的所有操作，便于审计和问题排查。

### 查看操作记录

1. 进入 **设置** → **活动日志**（或在资源详情页查看关联日志）
2. 日志列表默认按时间倒序显示

**日志条目包含：**

| 字段 | 说明 | 示例 |
|------|------|------|
| 时间 | 操作发生时间 | 2026-06-12 14:30:25 |
| 用户 | 执行操作的用户 | alice |
| 操作类型 | 操作分类 | 创建 / 更新 / 删除 / 导出 |
| 资源类型 | 操作的资源 | 数据集 / 训练任务 / 模型 / 部署 |
| 资源名称 | 资源标识 | yolov8n-custom |
| 详情 | 操作详细信息 | epochs 从 100 修改为 200 |
| IP 地址 | 操作来源 IP | 192.168.1.100 |

**记录的操作类型：**

- **数据集**：上传、删除、更新、下载

- **模型**：导出、删除、标签变更、版本回滚
- **部署**：创建、更新、停止、删除、扩缩容
- **团队**：成员添加/移除、角色变更、权限修改
- **系统**：用户登录/登出、密码修改、设置变更

## 版本控制

每个训练完成的模型都会自动创建一个版本：

```
v1.0.0 - 初始版本
v1.1.0 - 增加训练轮数
v1.2.0 - 调整学习率
v2.0.0 - 更换模型架构
```

### 版本标签

为模型打标签便于管理：

```bash
# 通过 API 添加标签
curl -X POST http://localhost:8000/api/v1/models/{id}/tags \
  -H "Authorization: Bearer token" \
  -d '{"tags": ["production", "best"]}'
```

**常用标签：**
- `production`：生产环境使用
- `staging`：测试环境使用
- `best`：当前最佳模型
- `archive`：归档版本

### 版本对比

1. 进入"模型管理" -> "版本对比"
2. 选择要对比的版本
3. 查看对比：
   - mAP 指标对比
   - 推理速度对比
   - 模型大小对比
   - 训练配置对比

### 版本回滚

如果新版本效果不好，可以回滚到历史版本：

1. 找到要回滚的版本
2. 点击"回滚到此版本"
3. 确认回滚
4. 系统会将该版本标记为当前版本

### 版本导出

导出模型用于部署：

1. 选择模型版本
2. 选择导出格式：
   - ONNX：通用格式
   - TensorRT：NVIDIA GPU 优化
   - CoreML：Apple 设备
   - TFLite：移动端
3. 下载导出文件

## 常见问题

### Q1: 训练速度很慢怎么办？

**可能原因：**
- GPU 未正确使用
- 数据加载瓶颈
- 图片尺寸太大

**解决方案：**
```json
{
  "config": {
    "device": "0",           // 确认使用 GPU
    "workers": 8,            // 增加数据加载线程
    "amp": true,             // 启用混合精度
    "img_size": 416,         // 减小图片尺寸
    "batch_size": 32         // 增加批量大小（如果显存允许）
  }
}
```

### Q2: 模型精度不高怎么办？

**可能原因：**
- 数据量不足
- 标注质量差
- 训练轮数不够
- 模型太小

**解决方案：**
1. 增加数据量和数据增强
2. 检查并修正标注错误
3. 增加训练轮数（epochs）
4. 使用更大的模型（如 YOLOv8m 或 YOLOv8l）
5. 调整学习率和优化器

### Q3: 如何选择合适的模型？

| 场景 | 推荐模型 |
|------|---------|
| 实时检测（移动端） | YOLOv8n / YOLOv10n |
| 通用场景 | YOLOv8s / YOLOv10s |
| 高精度需求 | YOLOv8m / YOLOv8l |
| 最高精度 | YOLOv8x |
| 资源受限 | YOLOv9c |

### Q4: 数据集格式不对怎么办？

**格式转换工具：**
```bash
# COCO 转 YOLO
python scripts/convert_coco_to_yolo.py --input coco.json --output yolo/

# VOC 转 YOLO
python scripts/convert_voc_to_yolo.py --input voc/ --output yolo/
```

### Q5: 训练中断了怎么办？

**恢复训练：**
1. 系统会自动保存 checkpoint
2. 在创建训练时选择"继续训练"
3. 选择上次的 checkpoint 文件
4. 继续训练

### Q6: 如何部署训练好的模型？

**导出为 ONNX：**
```bash
# 通过 API 导出
curl -X POST http://localhost:8000/api/v1/models/{id}/export \
  -H "Authorization: Bearer token" \
  -d '{"format": "onnx"}'
```

**使用 ONNX Runtime 推理：**
```python
import onnxruntime as ort
import numpy as np

session = ort.InferenceSession("model.onnx")
results = session.run(None, {"images": input_tensor})
```
